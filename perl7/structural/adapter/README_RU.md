# Адаптер

**Категория:** Структурные

## Какую проблему решает

Хочется использовать существующий класс или стороннюю библиотеку, но её интерфейс не совпадает с тем, что ожидает ваш код. Изменить библиотеку нельзя или нежелательно.

## Когда использовать

- Оборачивание стороннего платёжного SDK под внутренний интерфейс `PaymentGateway`
- Адаптация легаси-сервиса аутентификации к новому интерфейсу без правок легаси-кода
- Совместимость старого драйвера БД с современным интерфейсом репозитория
- Интеграция внешнего CSV/XML-источника как потока объектов предметной области

## Что вы получаете

- Использование существующего кода без его изменения
- Ваше приложение зависит только от собственного интерфейса — адаптер единственное место, знающее о внешней библиотеке
- Смена реализации = смена одного класса-адаптера

## Практические примеры

**Payment SDK:** Ваш код вызывает `gateway->charge($amount)`. Адаптер транслирует в `Stripe::charge({amount => $amount, currency => "usd"})`.

**SMTP-библиотека:** Ваш код вызывает `notifier->notify($recipient, $message)`. Адаптер вызывает `mailer->send_email($to, $subject, $body)`.

**Легаси API:** Новый обработчик ожидает интерфейс `UserStore`; адаптер оборачивает старый SOAP-клиент, предоставляя те же методы.

## Признаки того, что паттерн нужен

- Вызов `$thirdPartyLib->doTheThing($a, $b, $c)` встречается в 10 местах — он должен быть за вашим интерфейсом
- Вы передаёте объекты сторонних SDK через бизнес-логику вместо собственных доменных типов

## Run

```
perl -Ilib main.pl
```
