# Компоновщик

**Категория:** Структурные

## Какую проблему решает

Есть древовидная структура (меню, файловые системы, иерархии прав), и код должен работать с отдельными элементами (листьями) и группами элементов (контейнерами) единообразно, не проверяя тип каждого узла.

## Когда использовать

- Навигационные меню, где пункты могут содержать подменю
- Операции с файловой системой: файлы и директории поддерживают одни и те же методы
- Иерархии прав/ролей: роль может наследовать другие роли, права агрегируются рекурсивно
- SQL WHERE: `AND(OR(a=1, b=2), NOT(c=3))` — листья — условия, узлы — операторы
- UI-дерево компонентов: контейнеры и листья разделяют интерфейс `render()`

## Что вы получаете

- Клиентский код вызывает один и тот же метод на любом узле, не зная — лист это или контейнер
- Операции типа `size()` или `render()` автоматически распространяются по дереву через рекурсию
- Добавление нового типа узла не меняет клиентский код

## Практические примеры

**Построитель SQL WHERE:** Узлы `AND` и `OR` содержат дочерние выражения; листья — сравнения полей. `where->to_sql()` рекурсирует естественно.

**Роутинг:** Группа роутов и отдельный роут оба реализуют `handle($request)`. Группа делегирует детям; клиент работает с обоими одинаково.

**Конфиг:** Пространство имён и значение конфига оба отвечают на `get("key")`. Namespace рекурсирует в дочерние элементы.

## Признаки того, что паттерн нужен

- В нескольких местах пишете `if $item isa Container { ... } else { ... }` при обходе дерева
- Хотите вызывать один и тот же метод на "группах" и "отдельных элементах" без специальной обработки

## Run

```
perl -Ilib main.pl
```
