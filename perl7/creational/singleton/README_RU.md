# Одиночка

**Категория:** Порождающие

## Какую проблему решает

Некоторые ресурсы должны иметь ровно один экземпляр на всё приложение. Создание нескольких вызывает баги: дублирование соединений, конфликт конфигураций, раздробленный кэш.

## Когда использовать

- Пул соединений с БД — один пул на процесс, разделяемый везде
- Конфиг приложения — загружается один раз при старте, читается по всей кодовой базе
- Логгер — единственный экземпляр направляет все записи в одно место
- In-memory кэш — должен быть общим; два экземпляра = два раздробленных кэша

## Что вы получаете

- Гарантированно один экземпляр с глобальной точкой доступа
- Ленивая инициализация через `//=` — создаётся только при первом обращении
- Переменная `my $instance` внутри блока класса невидима снаружи

## Практические примеры

**Пул БД:** `DB->get_instance()` везде возвращает один объект. Несколько пулов упираются в лимит соединений.

**Логгер:** `Logger->get_instance()` всегда направляет записи в один файл/сервис.

**Фичефлаги:** Загружает флаги один раз из конфига и отдаёт все запросы из памяти.

## Признаки того, что паттерн нужен

- Передаёте один и тот же объект через несколько слоёв конструкторов
- Случайно создали два пула соединений и упёрлись в лимит
- Хотите гарантировать единственную инициализацию при старте

## Запуск

```
perl -Ilib main.pl
```
