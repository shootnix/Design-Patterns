# Фабричный метод

**Категория:** Порождающие

## Какую проблему решает

Базовый класс или фреймворк должен создавать объекты, но конкретный тип зависит от подкласса или контекста. Хочется избежать жёсткой привязки к конкретному типу.

## Когда использовать

- Базовый `Controller` создаёт объекты-ответы, но каждый подкласс должен порождать свой тип
- Каждый репозиторий создаёт свой объект запроса с типобезопасными скоупами
- Плагинная система, где каждый плагин регистрирует свой создатель
- Выбор транспорта: конкретный тип зависит от подкласса логистики

## Что вы получаете

- Базовый класс определяет контракт создания; подклассы решают, что именно создавать
- Новый тип = новый подкласс только — никаких изменений в базовом классе
- Алгоритм, использующий созданный объект, живёт в одном месте

## Практические примеры

**Веб-фреймворк:** Базовый класс определяет фабричный метод. Каждый подкласс возвращает свой конкретный тип — шаблонный метод работает одинаково для всех.

**ORM-репозиторий:** Базовый репозиторий определяет `create_query()`. Каждый репозиторий возвращает объект запроса со своими скоупами.

**Логистика:** `RoadLogistics` создаёт `Truck`; `SeaLogistics` — `Ship`. `plan_delivery()` работает с любым из них.

## Признаки того, что паттерн нужен

- Базовый класс создаёт объекты с жёстко заданным именем класса, которое подклассы не могут переопределить
- Вы пишете код библиотеки и хотите дать вызывающим возможность инжектировать конкретный тип

## Запуск

```
perl -Ilib main.pl
```
