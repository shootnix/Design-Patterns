# Прототип

**Категория:** Порождающие

## Какую проблему решает

Инициализация объекта дорогостоящая, или нужно много почти идентичных объектов с небольшими вариациями. Пересоздавать с нуля расточительно.

## Когда использовать

- Клонировать базовый объект запроса для вариантов с разными WHERE, сохраняя общие JOIN
- Загрузить тяжёлый конфиг один раз, клонировать и переопределять значения для каждого клиента
- Предварительно настроить сложные объекты и клонировать для каждого сценария
- Copy-on-write: разделять состояние до мутации, затем клонировать

## Что вы получаете

- Новые объекты создаются копированием — без повторной инициализации
- Клоны полностью независимы — мутация одного не затрагивает оригинал
- Реестр прототипов работает как именованная фабрика без знания конкретного класса

## Практические примеры

**Объекты запросов:** Клонируете базовый запрос и добавляете разные WHERE. Оба клона разделяют JOIN.

**Конфиг на клиента:** Загружаете мастер-конфиг один раз. Клонируете на каждый запрос и переопределяете специфичные значения.

**Шаблон API-ответа:** Предварительно собранный envelope клонируется на каждый запрос.

## Признаки того, что паттерн нужен

- Создаёте один и тот же объект многократно, меняя одно-два поля
- Инициализация медленная и происходит в горячем пути
- Хотите именованный «шаблон» объекта, который вызывающие копируют и настраивают

## Запуск

perl -Ilib main.pl
