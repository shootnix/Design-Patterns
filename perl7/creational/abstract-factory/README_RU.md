# Абстрактная фабрика

**Категория:** Порождающие

## Какую проблему решает

Нужно создавать семейства связанных объектов, где конкретный набор зависит от выбора в рантайме, и этот выбор не должен расползаться по всему коду.

## Когда использовать

- Приложение поддерживает несколько платёжных провайдеров (Stripe, PayPal, Braintree), каждый требует согласованный набор: обработчик платежей, возвратов, вебхуков
- ORM должен работать с несколькими СУБД (PostgreSQL, MySQL, SQLite), у каждой своя: соединение, построитель запросов, менеджер схемы
- Мультиоблачная настройка: AWS/GCP/Azure как согласованный набор клиентов
- Мультиарендная SaaS, где у каждого клиента своя интеграция, выбираемая при старте

## Что вы получаете

- Один объект-фабрика на «семейство» — остальной код знает только интерфейсы
- Новый провайдер = один новый класс, нулевые изменения в существующем коде
- Согласованные семейства — невозможно случайно смешать объекты разных провайдеров

## Практические примеры

**Платёжная обработка:** Фабрика создаёт `PaymentGateway + RefundGateway + WebhookVerifier` как согласованный набор. Меняете фабрику в одном месте — все обработчики обновляются.

**Абстракция над БД:** Фабрика для PostgreSQL создаёт соединение, построитель запросов и менеджер схемы. Переключаетесь на MySQL — меняете только фабрику.

**Уведомления:** Фабрика создаёт `Sender + TemplateRenderer + DeliveryTracker` для каждого провайдера.

## Признаки того, что паттерн нужен

- В нескольких местах есть `if $provider eq 'stripe' { ... } elsif ...`, создающий разные объекты
- Добавление нового провайдера требует правок во многих файлах

## Запуск

```
perl -Ilib main.pl
```
