# Прототип

**Категория:** Порождающие

## Какую проблему решает

Инициализация объекта дорогостоящая, или нужно много почти идентичных объектов с небольшими вариациями. Пересоздавать с нуля каждый раз расточительно.

## Когда использовать

- Клонировать базовый объект запроса для вариантов с разными WHERE, сохраняя общие JOIN
- Загрузить тяжёлый конфиг один раз, затем клонировать и переопределять значения для каждого клиента или запроса
- Предварительно настроить сложные объекты (HTTP-клиенты, форматтеры) и клонировать для каждого сценария
- Copy-on-write: разделять состояние до мутации, затем клонировать

## Что вы получаете

- Новые объекты создаются копированием — без повторной дорогостоящей инициализации
- Клоны полностью независимы — мутация одного не затрагивает оригинал
- Реестр прототипов работает как именованная фабрика без знания конкретного класса

## Практические примеры

**Объекты запросов:** `$base->clone()` → добавить `.where("status = 'active'")` на один клон, `.where("status = 'pending'")` на другой. Оба разделяют JOIN.

**Конфиг на клиента:** Загружаете конфиг один раз. На каждый запрос: `$cfg = $master->clone(); $cfg->{tenant_id} = $id`. Никаких повторных чтений.

**Шаблон API-ответа:** Предварительно собранный envelope клонируется на каждый запрос и заполняется данными.

## Признаки того, что паттерн нужен

- Вызываете `MyObject->new(...)` многократно с почти одинаковыми значениями, меняя одно-два поля
- Инициализация медленная и происходит в горячем пути
- Хотите «шаблон» объекта, который вызывающие копируют и настраивают
