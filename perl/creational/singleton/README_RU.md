# Одиночка

**Категория:** Порождающие

## Какую проблему решает

Некоторые ресурсы должны иметь ровно один экземпляр на всё приложение. Создание нескольких вызывает баги: дублирование соединений, конфликт конфигураций, раздробленный кэш.

## Когда использовать

- Пул соединений с БД — один пул на процесс, разделяемый везде
- Конфиг приложения — загружается один раз при старте, читается по всей кодовой базе
- Логгер — единственный экземпляр направляет все записи в одно место
- In-memory кэш — должен быть общим; два экземпляра = два кэша, не видящих данные друг друга

## Что вы получаете

- Гарантированно один экземпляр с глобальной точкой доступа
- Ленивая инициализация — создаётся только при первом обращении
- Лексикальная `my $instance` внутри пакета скрывает конструктор от внешнего кода

## Практические примеры

**Пул БД:** `DB->get_instance()` везде возвращает один объект. Два пула расходуют соединения вдвойне.

**Логгер:** `Logger->get_instance()->log("request received")` всегда направляет записи в один файл/сервис.

**Фичефлаги:** `FeatureFlags->get_instance()` загружает флаги один раз из конфига и отдаёт все запросы из памяти.

## Признаки того, что паттерн нужен

- Передаёте один и тот же объект через несколько слоёв конструкторов ради совместного использования
- Случайно создали два пула соединений и упёрлись в лимит БД
- Хотите гарантировать единственную инициализацию при старте

## Запуск

```
perl main.pl
```
