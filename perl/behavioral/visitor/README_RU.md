# Посетитель

**Категория:** Поведенческие

## Какую проблему решает

Нужно добавить новые операции к стабильной иерархии объектов без изменения этих классов. Каждая операция инкапсулируется в отдельном классе-посетителе, а элементы иерархии принимают любого посетителя.

## Когда использовать

- Обработка AST: линтинг, форматирование, компиляция, анализ кода без правок классов узлов AST
- Экспорт документов: одна и та же модель документа экспортируется как HTML, PDF, Markdown — каждый экспорт — посетитель
- Анализ схемы ORM: генерация миграций, документации и ER-диаграмм из одной и той же модели сущностей без её изменения
- Операции над корзиной: расчёт итога, применение скидки, налог, сериализация для доставки — каждое — посетитель
- Отчётность: сбор статистики, генерация сводок, экспорт в CSV — всё по одной и той же структуре данных

## Что вы получаете

- Новые операции добавляются как новые классы-посетители — иерархия элементов никогда не меняется
- Вся логика одной операции живёт в одном классе-посетителе вместо распределения по классам элементов
- Несколько посетителей работают с одной структурой независимо друг от друга

## Практические примеры

**Экспорт сущностей ORM:** `MigrationVisitor` генерирует SQL `CREATE TABLE`, `DocumentationVisitor` — API-документацию, `SerializerVisitor` — JSON-схему. Все — по одному и тому же дереву `EntityDefinition`.

**Экспорт документа:** `HTMLExporter` и `MarkdownExporter` оба обходят `Paragraph`, `Heading`, `Image`. Узлы реализуют только `accept($visitor)` и ничего не знают о форматах экспорта.

**Операции над фигурами:** `AreaVisitor` вычисляет суммарную площадь; `SVGVisitor` генерирует SVG-разметку. Оба обходят `Circle` и `Rectangle` — одни фигуры, разные операции.

## Признаки того, что паттерн нужен

- Постоянно добавляете методы в классы элементов для новых операций: `to_html()`, `to_markdown()`, `to_pdf()`, `to_csv()` — они принадлежат отдельным классам-посетителям
- Хотите добавить операцию в иерархию классов, которую вы не можете изменить (сторонняя библиотека) — посетитель позволяет это без правок библиотеки
