# Итератор

**Категория:** Поведенческие

## Какую проблему решает

Клиентскому коду нужно последовательно обходить коллекцию, не зная её внутреннюю структуру — индексы, курсоры, токены страниц. Логика обхода должна быть независима от типа коллекции.

## Когда использовать

- Потоковое считывание результатов большого запроса строка за строкой без загрузки всего в память
- Пагинация API-ответов: клиент вызывает `next()`, не зная о токенах страниц или расчёте смещений
- Обход дерева или графа в заданном порядке (DFS, BFS) без управления стеком в клиентском коде
- Чтение больших файлов построчно без удержания всего файла в памяти

## Что вы получаете

- Единый интерфейс `has_next() / next()` независимо от того, что внутри коллекции
- Коллекция остаётся инкапсулированной — внутренняя структура может меняться без поломки клиентов
- Несколько независимых итераторов могут обходить одну коллекцию одновременно

## Практические примеры

**Курсор БД:** `ResultSetIterator` считывает строки большого запроса потоково. Клиент вызывает `next()` без знания о буферизации; память остаётся постоянной.

**Пагинированный API:** `APIPageIterator` загружает следующую страницу по требованию. Клиент видит плоскую последовательность без управления токенами.

**Читатель строк:** `LineIterator` читает большой лог-файл построчно. Клиент итерирует, не удерживая весь файл в памяти.

## Признаки того, что паттерн нужен

- Возвращаете огромный список, хотя лучше было бы потоковое чтение — клиенту не нужны все элементы сразу
- В нескольких местах обходите коллекцию одинаковым циклом по индексу — этот обход принадлежит итератору
- Есть пользовательская структура данных, которую вызывающие должны обходить
