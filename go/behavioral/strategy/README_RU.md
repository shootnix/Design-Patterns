# Стратегия

**Категория:** Поведенческие

## Какую проблему решает

Есть несколько взаимозаменяемых алгоритмов или политик для задачи, и нужно выбирать один в рантайме без изменения кода, использующего результат. Выбор алгоритма должен быть инжектируемым и тестируемым независимо.

## Когда использовать

- Аутентификация: JWT, OAuth2, API-ключ, сессия — выбор стратегии на роут или среду
- Маршрутизация платежей: выбор процессора (Stripe, PayPal, банковский перевод) по сумме, валюте или стране
- Сортировка или пагинация: разные алгоритмы сортировки для разных объёмов данных; offset vs cursor пагинация
- Сжатие: gzip или brotli на основе заголовка Accept-Encoding
- Ценообразование: фиксированная цена, динамическое ценообразование, скидка для подписчиков — выбор на этапе checkout
- Бэкенд кеширования: Redis, Memcached или in-memory — инжектируется; бизнес-логика не меняется

## Что вы получаете

- Выбор алгоритма отвязан от кода, использующего результат
- Новые стратегии добавляются без изменения существующего кода (Open/Closed Principle)
- Каждая стратегия независимо тестируется; в тестах вызывающего — мок стратегии

## Практические примеры

**Auth-middleware:** `AuthMiddleware` получает `Strategy` и вызывает `authenticate($request)`. Замена `JWTStrategy` на `APIKeyStrategy` на конкретный роут — код middleware не меняется.

**Sorter:** `$sorter->set_strategy(BubbleSort->new())`, затем `->sort(@data)`. Замена на `StdSort` — вызывающий код идентичен.

**Ценообразование:** `PriceCalculator->calculate($order)` делегирует `FixedPricingStrategy`, `DynamicPricingStrategy` или `SubscriberPricingStrategy` в зависимости от уровня пользователя.

## Признаки того, что паттерн нужен

- В обработчике есть `if $algorithm eq "jwt" { ... } elsif ...` — этот блок принадлежит классу стратегии
- Бизнес-логику нельзя тестировать независимо от используемого алгоритма — инжектируйте его как стратегию
- Алгоритм выбирается через переменную окружения или конфиг — выбор уже внешний, код должен это отражать
