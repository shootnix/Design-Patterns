# Шаблонный метод

**Категория:** Поведенческие

## Какую проблему решает

Несколько классов разделяют одну и ту же структуру алгоритма, но различаются в конкретных шагах. Без паттерна копируется скелет с вариацией только деталей — любое изменение общих шагов нужно вносить в каждую копию.

## Когда использовать

- Генераторы отчётов: CSV, HTML, JSON-отчёты следуют `header -> rows -> footer`, но с разным форматированием
- Импортёры данных: CSV и JSON оба `open -> parse -> validate -> save -> close`, но парсят по-разному
- Обработчики HTTP-запросов: все `authenticate -> authorize -> validate -> process -> respond`, но process разный
- ORM: `find()` следует `buildQuery -> execute -> mapResults` — разные ORM реализуют каждый шаг по-своему
- Жизненный цикл тестов: `setUp -> run -> tearDown` — подклассы переопределяют `run()` и опционально `setUp/tearDown`

## Что вы получаете

- Скелет алгоритма определён один раз в базовом классе — подклассы переопределяют только отличающиеся шаги
- Общие шаги (обработка ошибок, логирование, освобождение ресурсов) написаны один раз и применяются везде
- Новый формат или импортёр = новый подкласс; скелет не меняется

## Практические примеры

**Генератор отчётов:** Базовый `Report` имеет `generate()`, вызывающий `header()`, `body($rows)`, `footer()`. `CSVReport` и `HTMLReport` реализуют три шага по-разному. Цикл generate идентичен.

**Импортёр данных:** Базовый `Importer` определяет `import()` = open, parse, validate, save. `CSVImporter` переопределяет только `parse()`. `JSONImporter` — тоже только `parse()`, но иначе. Остальное разделяется.

**HTTP-обработчик:** Базовый `APIHandler` имеет `handle()` = authenticate, authorize, validate, process, respond. Подклассы переопределяют только `process()`.

## Признаки того, что паттерн нужен

- Два класса с почти идентичными методами — различаются только 1–2 внутренних шага
- Копируете 20-строчный метод и меняете 3 строки в середине — эти 3 строки должны быть переопределяемым методом
