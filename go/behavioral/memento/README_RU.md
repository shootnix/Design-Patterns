# Снимок

**Категория:** Поведенческие

## Какую проблему решает

Нужно сохранить состояние объекта и восстановить его позже — для undo, отката или чекпоинтов — не раскрывая внутреннюю реализацию объекта коду, хранящему снимок.

## Когда использовать

- Многошаговый мастер форм: сохранять состояние перед переходом к следующему шагу, чтобы пользователь мог вернуться
- Undo/redo в текстовом или коде-редакторе: снимок перед каждым изменением, восстановление по Ctrl+Z
- Откат транзакции БД: снимок состояния сущности перед операцией, которая может упасть
- Автосохранение черновика: сохранять каждые 30 секунд; восстанавливать при сбое
- Отслеживание изменений ORM: снимок полей после загрузки; сравнение с текущими значениями для определения изменившихся

## Что вы получаете

- Состояние объекта захвачено в непрозрачном снимке (Memento) — только создатель может прочитать его содержимое
- Стек снимков обеспечивает многоуровневый undo
- Состояние восстанавливается чисто без пересоздания объекта с нуля или раскрытия внутренних полей

## Практические примеры

**Мастер форм:** Перед переходом к шагу 3 `$form->save()` создаёт снимок. Если пользователь нажимает "Назад", `$form->restore($memento)` возвращает точное предыдущее состояние.

**Текстовый редактор:** `$editor->type("Hello"); $history->push($editor->save())`. Ctrl+Z извлекает снимок из стека и вызывает `$editor->restore($memento)`.

**Отслеживание изменений ORM:** После загрузки записи — снимок полей. Перед сохранением — сравнение с текущими: в UPDATE попадают только изменившиеся колонки.

## Признаки того, что паттерн нужен

- Хотите undo и понимаете, что нужно запомнить всё предыдущее состояние, а не только последнее действие
- Сериализуете объект в словарь или JSON только чтобы передать его и потом восстановить — это по сути и есть снимок
