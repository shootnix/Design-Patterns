# Приспособленец

**Категория:** Структурные

## Какую проблему решает

Создаётся большое количество похожих объектов, большинство данных которых одинаковы. Повторяющиеся общие данные расходуют память. Приспособленец разделяет общее (внутреннее состояние) и уникальное (внешнее состояние).

## Когда использовать

- Рендеринг больших таблиц: тысячи ячеек разделяют одинаковое форматирование (шрифт, цвет, рамка)
- ORM: тысячи загруженных строк модели разделяют одни и те же метаданные колонок — различаются только значения ячеек
- Игровой движок: тысячи врагов одного типа разделяют текстуру и форму коллизии; различается только позиция
- Рендеринг карты: одна и та же тайловая текстура отрисовывается в тысячах позиций
- Генерация PDF: один и тот же глиф символа рисуется в разных позициях страницы

## Что вы получаете

- Общее «внутреннее состояние» хранится один раз в объекте-приспособленце; на экземпляр хранится только уникальное «внешнее состояние»
- Существенная экономия памяти: 1000 деревьев трёх типов = 3 объекта, не 1000
- Фабрика/реестр гарантирует повторное использование приспособленца, а не его дублирование

## Практические примеры

**Метаданные колонок ORM:** Модель `User` загружает 10 000 строк — каждая строка ссылается на одни и те же объекты `ColumnDefinition` для `id`, `name`, `email`. Различаются только значения.

**Лес деревьев:** `TreeType` (вид + цвет + текстура) — приспособленец. `Tree` (x, y + ссылка на `TreeType`) — контекст. 10 000 деревьев пяти видов = 5 объектов.

**Стили ячеек:** `CellStyle` (шрифт, фон, рамка) — приспособленец. Многие ячейки ссылаются на один стиль; различаются только их содержимое и позиция.

## Признаки того, что паттерн нужен

- Профилировка памяти показывает тысячи объектов с одинаковыми полями кроме одного-двух
- В объектах чётко выделяются «данные типа» (общие для многих) и «данные экземпляра» (уникальные)
- Вы строите систему рендеринга, симуляции или обработки данных с большим масштабом
