# Строитель

**Категория:** Порождающие

## Какую проблему решает

Объект требует множества параметров, большинство из которых опциональны — это приводит к конструкторам с 10+ аргументами или громоздким конфиг-структурам, которые тяжело читать и легко использовать неверно.

## Когда использовать

- Построение SQL-запросов: `SELECT ... FROM ... WHERE ... ORDER BY ... LIMIT ...`
- Конструирование HTTP-запросов с опциональными заголовками, телом, таймаутом, политикой ретраев
- Создание сложных объектов предметной области (`UserProfile`, `ReportConfig`) с множеством опциональных полей
- Пошаговая генерация HTML, email-шаблонов или CLI-команд

## Что вы получаете

- Читаемый fluent API: `.WithTimeout(30).WithRetry(3).Build()`
- Каждый setter возвращает builder — логика построения компонуется и читается как текст
- Финальный объект иммутабелен и полностью проверен после вызова `Build()`
- Легко получать множество конфигураций из одной и той же базы builder'а

## Практические примеры

**SQL query builder:** `NewQuery().Select("id","name").From("users").Where("active = true").OrderBy("name").Limit(10).Build()`

**HTTP-запрос:** `NewRequest(POST, "/api/users").Header("Authorization", token).JSONBody(payload).Timeout(5*time.Second).Build()`

**Email:** `NewEmail().To("user@example.com").Subject("Добро пожаловать").HTMLBody(html).Attach(pdf).Build()`

## Признаки того, что паттерн нужен

- В конструкторе более 4–5 параметров, большинство опциональны
- Вы используете map или config-структуру только ради передачи опциональных аргументов в конструктор
- `New(nil, "", 0, true, nil, "default", 30)` — невозможно понять без чтения сигнатуры
